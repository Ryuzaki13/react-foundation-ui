# Семантические цветовые токены

## Назначение и границы контракта

Контракт описывает фоновые поверхности, акцентное оформление, границы, выбранные состояния, фокус, подсветку текста и статусы.

Токены описывают **назначение цвета**, а не конкретный оттенок, компонент или приоритет команды. Одна тема может использовать одинаковые значения для нескольких ролей; другая — разделять их. Компоненты продолжают обращаться к тем же именам.

| Семейство            | Назначение                               | Примеры                                               |
| -------------------- | ---------------------------------------- | ----------------------------------------------------- |
| `--bg-*`             | Поверхности и нейтральная реакция        | Содержимое панели, служебная шапка, внутреннее поле   |
| `--accent-*`         | Визуально выразительное оформление       | Заголовок, иконка, залитая кнопка, акцентный контур   |
| `--border-*`         | Нейтральные границы и декоративные линии | Разделитель, рамка панели, граница поля               |
| `--selection-*`      | Сохраняющееся выбранное состояние        | Выбранная опция, строка, карточка, сегмент            |
| `--focus-ring`       | Видимый индикатор фокуса                 | Контур элемента, к которому направлено взаимодействие |
| `--text-selection-*` | Пользовательское выделение текста        | Фрагмент, выделенный мышью или клавиатурой            |
| `--highlight-*`      | Подсветка релевантного содержимого       | `<mark>`, поисковое совпадение, текущее совпадение    |

**Тема задаёт цвета. Компонент связывает их со своими частями и состояниями. Приложение определяет значение элементов в пользовательском сценарии.**

Например, `accent` не означает «основное действие». Один и тот же набор подходит для выразительного заголовка и кнопки. Какая из команд должна быть заметнее остальных, решается на уровне экрана, а не имени цветового токена.

Токены этой группы не задают размеры, толщину линий, скругления, порядок слоёв или анимацию. Цвет также не заменяет HTML-семантику, обработчики событий и управление состоянием.

## Структура имени

Основная схема:

```text
--<назначение>-<часть>[-<состояние>]

--accent-fill-hover
  назначение: accent
  часть:      fill
  состояние: hover
```

| Часть имени | Значение                                                   |
| ----------- | ---------------------------------------------------------- |
| `text`      | Текст и одноцветные иконки на предусмотренном для них фоне |
| `border`    | Граница, контур или линия соответствующего назначения      |
| `bg`        | Подложка; внутри `selection` — мягкое выделение            |
| `fill`      | Насыщенная акцентная заливка, а не обычная поверхность     |
| `on-fill`   | Текст и иконки непосредственно на насыщенной заливке       |
| `hover`     | Временная реакция на наведение                             |
| `pressed`   | Временная реакция в процессе нажатия                       |
| `disabled`  | Недоступность взаимодействия                               |
| `current`   | Текущее совпадение в поисковой навигации                   |

Отсутствие суффикса означает базовое состояние **внутри семейства**. Поэтому `--selection-bg` уже означает фон выбранного элемента, а не фон любого элемента списка.

Названия частей не ограничивают технику отрисовки. Например, цвет линии `--selection-border` допустимо применить к `border-bottom`, `box-shadow` или фону узкого псевдоэлемента. Но окрашивать им всю поверхность карточки вместо `--selection-bg` — нарушение назначения.

Ни один токен не требует «обязательно стать темнее при наведении». Направление изменения яркости, оттенка и насыщенности определяется темой; смысл состояния остаётся неизменным.

## Фоновые поверхности: `--bg-*`

| Токен | Назначение |
| --- | --- |
| `--bg-canvas` | Общая подложка приложения |
| `--bg-surface` | Обычная самостоятельная поверхность с содержимым |
| `--bg-elevated` | Основная поверхность всплывающего компонента |
| `--bg-secondary` | Нейтральный фон вспомогательной структурной области внутри компонента |
| `--bg-sunken` | Утопленная рабочая область: поле, редактор, блок кода |
| `--bg-hover` | Временная реакция нейтрального элемента на наведение |
| `--bg-pressed` | Временная реакция нейтрального элемента в процессе нажатия |
| `--bg-accent` | Намеренно акцентированная область без состояния выбора |
| `--bg-disabled` | Фон недоступного элемента |
| `--bg-overlay` | Полупрозрачная подложка позади модального слоя |

`secondary` описывает роль поверхности относительно основного содержимого. Он подходит для шапки, панели команд, области действий или внутренней секции метаданных. Самостоятельная панель с основным содержимым остаётся `surface`. Вспомогательная область не получает собственный уровень возвышения, статус, выбранность или недоступность.

Поверхность всплывающего компонента использует `elevated`, но его внутренние части могут отличаться по цвету:

```text
Modal                         bg-elevated
├── Шапка                     bg-secondary
├── ModalToolbar              bg-secondary
├── ModalContent              прозрачный фон
└── ModalFooter               bg-secondary
```

Заголовок на `bg-secondary` продолжает использовать `text-primary`: название фона не определяет важность текста. Состояния вложенных кнопок и полей сохраняют свои роли `hover`, `pressed`, `selection`, `disabled` и статусов.

Тема задаёт `--bg-secondary` независимо от `surface`, `elevated` и `sunken` через обычную карту `tokens` публичного mixin `theme($mode, $overrides: ())`. Класс `bgSecondary` доступен в `styles/foundation`, чтобы приложение могло оформить свои служебные секции без дополнительных компонентных API.

## 1. Акцентное оформление: `--accent-*`

**Назначение:** сделать элемент визуально выразительным, не присваивая ему семантику выбора, ошибки или фокуса.

Семейство подходит как интерактивным, так и статическим элементам. Наличие состояний `hover` и `pressed` не делает заголовок интерактивным: он использует только базовый текстовый токен.

### Акцентный текст

| Токен                   | Назначение                                                     |
| ----------------------- | -------------------------------------------------------------- |
| `--accent-text`         | Акцентный текст или иконка на обычной поверхности              |
| `--accent-text-hover`   | Тот же текст или иконка при наведении на интерактивный элемент |
| `--accent-text-pressed` | Тот же текст или иконка в процессе нажатия                     |

Примеры: заголовок обложки, выразительное число в карточке, акцентная иконка, надпись кнопки без насыщенной заливки.

```scss
.heroTitle,
.accentIcon {
  color: var(--accent-text);
}
```

**`--accent-text` — не цвет содержимого на `--accent-fill`.** Он подбирается для обычных поверхностей, которые поддерживает компонент: например, `--bg-canvas`, `--bg-surface` или `--bg-elevated`. Пригодность для произвольного изображения, градиента или цветной заливки не подразумевается.

Существующие `--text-link` и `--text-link-hover` сохраняют роль обычных ссылок. Ссылка не должна переходить на `accent-text` только потому, что её можно нажать.

### Акцентная граница

| Токен                     | Назначение                                          |
| ------------------------- | --------------------------------------------------- |
| `--accent-border`         | Выразительная акцентная граница в обычном состоянии |
| `--accent-border-hover`   | Акцентная граница при наведении                     |
| `--accent-border-pressed` | Акцентная граница в процессе нажатия                |

Примеры: контур акцентной кнопки, выразительная рамка блока, акцентная линия рядом с заголовком.

Акцентная рамка сама по себе **не означает выбранность**. Выбранная карточка использует `--selection-border`; обычная выразительно оформленная карточка — `--accent-border`.

Для контурного элемента естественная пара — `--accent-text` и `--accent-border` на обычной поверхности. Состояния текста и границы выбираются согласованно. Компонент может использовать только часть семейства: наличие токена границы не обязывает добавлять рамку к заголовку или текстовой кнопке.

### Акцентная заливка

| Токен                   | Назначение                                        |
| ----------------------- | ------------------------------------------------- |
| `--accent-fill`         | Насыщенная акцентная заливка в обычном состоянии  |
| `--accent-fill-hover`   | Эта заливка при наведении                         |
| `--accent-fill-pressed` | Эта заливка в процессе нажатия                    |
| `--accent-on-fill`      | Текст и иконки на любой из трёх акцентных заливок |

Примеры: залитая кнопка, акцентный бейдж без статусного смысла, небольшой выразительный блок.

```scss
.accentBadge {
  color: var(--accent-on-fill);
  background-color: var(--accent-fill);
}
```

`--accent-on-fill` образует проверяемую пару с каждой заливкой: базовой, `hover` и `pressed`. В текущем контракте его цвет не меняется при наведении и нажатии. Поэтому тема должна подбирать три фона с учётом одного цвета содержимого.

Различие со смежными фоновыми токенами:

| Задача                           | Токен              |
| -------------------------------- | ------------------ |
| Обычная поверхность панели       | `--bg-surface`     |
| Мягко акцентированная секция     | `--bg-accent`      |
| Насыщенная акцентная область     | `--accent-fill`    |
| Содержимое на насыщенной области | `--accent-on-fill` |

Совпадение `accent-text`, `accent-border` и `accent-fill` в одной теме допустимо, но не является требованием. Нельзя рассчитывать, что в другой теме они останутся равны.

### Недоступный акцентный элемент

В этой группе нет `--accent-*-disabled`. Обычный недоступный акцентный контрол переходит на нейтральные роли:

```scss
color: var(--text-disabled);
background-color: var(--bg-disabled);
border-color: var(--border-interactive-disabled);
```

Для варианта без заливки допустимо сохранить прозрачный фон: недоступность не должна автоматически превращать текстовую кнопку в залитую.

## 2. Границы: `--border-*`

### Нейтральные границы

| Токен              | Назначение                               | Применение                                          |
| ------------------ | ---------------------------------------- | --------------------------------------------------- |
| `--border-subtle`  | Малозаметное визуальное разделение       | Разделители строк и секций, деликатная рамка панели |
| `--border-default` | Обычная граница самостоятельной области  | Карточка, контейнер, панель                         |
| `--border-strong`  | Намеренно выраженная нейтральная граница | Усиленное разделение областей, заметный контур      |

Эти три токена описывают степень выраженности **обычной границы**, а не состояния взаимодействия. `strong` не означает фокус, выбор или ошибку.

`subtle` описывает цветовую выразительность, не толщину. Толщина задаётся отдельно, например через `--border-width`.

```scss
.panel {
  background-color: var(--bg-surface);
  border: var(--border-width) solid var(--border-default);
}
```

### Граница интерактивного элемента

| Токен                           | Назначение                                       |
| ------------------------------- | ------------------------------------------------ |
| `--border-interactive`          | Базовая граница обычного, не акцентного контрола |
| `--border-interactive-hover`    | Его граница при наведении                        |
| `--border-interactive-pressed`  | Его граница в процессе нажатия                   |
| `--border-interactive-disabled` | Его граница при недоступности                    |

Примеры: поле ввода, нейтральная контурная кнопка, селект, интерактивная область без собственного акцентного оформления.

`--border-interactive` не является «ещё более сильным `border-strong`». Это отдельная роль с собственной последовательностью состояний.

Компонент не обязан использовать все состояния. Наличие `--border-interactive-pressed` не требует держать поле ввода в нажатом оформлении всё время редактирования. Ошибка валидации также не является `pressed`: её оформление относится к статусным токенам вне этой группы.

### Декоративная линия

**`--border-decorative` — цвет линии, которая участвует в композиции, но не сообщает состояние.**

Примеры: линия под заголовком, цветной вертикальный штрих, декоративный разделитель секций.

```scss
.sectionHeading {
  border-block-end:
    var(--border-width) solid var(--border-decorative);
}
```

У токена нет состояний наведения и нажатия. Для интерактивного контура используется соответствующее интерактивное семейство.

Декоративная линия может иметь тот же цвет, что и фокус, но настраивается независимо. Она не должна зависеть от `--focus-ring`: изменение доступного индикатора фокуса не должно перекрашивать оформление секций.

`--accent-border` означает линию общей акцентной семьи. `--border-decorative` означает самостоятельную декоративную роль; это не «второй акцент для любых задач».

## 3. Видимый фокус: `--focus-ring`

**Назначение:** показать, к какому элементу направлено взаимодействие при навигации.

Для элементов с DOM-фокусом типичная привязка — `:focus-visible`. Этот псевдокласс учитывает решение браузера о необходимости показать индикатор, а не исключительно факт нажатия клавиши Tab. [^selectors]

```scss
.control:focus-visible {
  outline: var(--focus-width) solid var(--focus-ring);
  outline-offset: var(--focus-offset);
}
```

Токен задаёт только цвет. Ширина, отступ, форма контура и защита от обрезания находятся в ответственности компонента и геометрических токенов.

**Фокус дополняет другие состояния, а не заменяет их.** У выбранной опции могут одновременно оставаться подложка `selection-bg`, текст `selection-text`, граница `selection-border` и отдельный контур `focus-ring`. Выбор и фокус действительно являются разными состояниями интерфейса. [^keyboard]

В составных компонентах с `aria-activedescendant` DOM-фокус может оставаться на контейнере или поле, а активный дочерний элемент задаётся атрибутом. Такой компонент должен сам связать визуальный индикатор с активным элементом: одного `:focus-visible` на каждой опции недостаточно. [^aria]

При отрицательном `--focus-offset` контур оказывается внутри элемента. Его необходимо проверять на заливке компонента; внешний контур проверяется на окружающей поверхности. Особенно важны насыщенные `accent-fill` и `selection-fill`. [^nontext]

Не следует использовать `focus-ring` для декоративных линий, границ ошибок или выбранности. Свечение также не заменяет различимый контур фокуса.

## 4. Выбранное состояние: `--selection-*`

**Назначение:** показать сохраняющийся выбор пользователя.

Примеры: выбранная опция, строка, вкладка, карточка, включённый сегмент, отмеченный элемент выбора. Выбор может сохраняться после перемещения указателя и ухода фокуса. [^keyboard]

Это визуальная роль, а не требование использовать везде `aria-selected`. Атрибут состояния выбирается по компоненту: у опций и вкладок это может быть `aria-selected`, у checkbox — нативный `checked` или `aria-checked`, у кнопки-переключателя — `aria-pressed`. [^aria] [^button]

Семейство предлагает **два варианта оформления выбранности: мягкую подложку и насыщенную заливку**. Вариант определяет компонент; тема подставляет подходящие значения.

### Мягкая подложка и текст

| Токен                       | Назначение                                     |
| --------------------------- | ---------------------------------------------- |
| `--selection-bg`            | Мягкий фон выбранного элемента                 |
| `--selection-bg-hover`      | Фон уже выбранного элемента при наведении      |
| `--selection-bg-pressed`    | Фон уже выбранного элемента в процессе нажатия |
| `--selection-bg-disabled`   | Фон выбранного, но недоступного элемента       |
| `--selection-text`          | Текст и иконки на базовой мягкой подложке      |
| `--selection-text-hover`    | Текст и иконки на `--selection-bg-hover`       |
| `--selection-text-pressed`  | Текст и иконки на `--selection-bg-pressed`     |
| `--selection-text-disabled` | Содержимое на `--selection-bg-disabled`        |

Это подходящий вариант для больших областей: строк, пунктов списка, карточек. Его задача — сохранить читаемость содержимого и показать выбор без насыщенной заливки всей площади.

```scss
.selectedCard {
  color: var(--selection-text);
  background-color: var(--selection-bg);
  border: var(--border-width) solid var(--selection-border);
}
```

**`selection-bg-hover` не предназначен для наведения на ещё не выбранный элемент.** Невыбранная нейтральная строка использует `--bg-hover`. Выбранная строка остаётся внутри семейства `selection`, чтобы наведение не скрывало выбор.

Текст и подложка переключаются согласованно. Например, `selection-text-pressed` проверяется на `selection-bg-pressed`, а не только на базовом фоне.

### Граница выбранности

| Токен                         | Назначение                                             |
| ----------------------------- | ------------------------------------------------------ |
| `--selection-border`          | Контур выбранного элемента                             |
| `--selection-border-hover`    | Этот контур при наведении                              |
| `--selection-border-pressed`  | Этот контур в процессе нажатия                         |
| `--selection-border-disabled` | Контур сохраняющейся выбранности недоступного элемента |

Граница может быть полной рамкой, нижней линией вкладки или боковым индикатором строки. Компонент выбирает форму; токен задаёт цвет.

В мягком варианте граница используется вместе с соответствующими `selection-bg` и `selection-text`. В насыщенном варианте её применение допустимо, но проверяется отдельно: различимость контура на `selection-fill` не подразумевается автоматически.

### Насыщенная заливка и содержимое

| Токен                          | Назначение                                             |
| ------------------------------ | ------------------------------------------------------ |
| `--selection-fill`             | Насыщенный фон выбранного элемента                     |
| `--selection-fill-hover`       | Этот фон при наведении                                 |
| `--selection-fill-pressed`     | Этот фон в процессе нажатия                            |
| `--selection-fill-disabled`    | Насыщенный вариант выбранности при недоступности       |
| `--selection-on-fill`          | Текст и иконки на базовой заливке, `hover` и `pressed` |
| `--selection-on-fill-disabled` | Содержимое на `selection-fill-disabled`                |

Примеры: залитый выбранный сегмент, компактный выбранный переключатель, внутренняя выбранная область контрола.

```scss
.selectedSegment {
  color: var(--selection-on-fill);
  background-color: var(--selection-fill);
}
```

Для насыщенного варианта нельзя автоматически брать `--selection-text`: он предназначен для мягкой подложки. Правильная пара — `selection-fill` и `selection-on-fill`.

### Выбранность при недоступности

Недоступность означает, что пользователь сейчас не может изменить состояние. Она не означает, что выбор исчез.

Поэтому выбранный недоступный элемент использует `selection-*-disabled`, а не безусловно переходит на полностью нейтральные цвета. Пользователь должен различать «не выбрано», «выбрано» и «выбрано, но изменение недоступно».

Готовые disabled-цвета не следует автоматически дополнительно умножать на `--disabled-opacity`: результат будет зависеть от фоновой поверхности и может оказаться чрезмерно бледным. Дополнительная прозрачность требует отдельной проверки.

## 5. Пользовательское выделение: `--text-selection-*`

| Токен                   | Назначение                            |
| ----------------------- | ------------------------------------- |
| `--text-selection-bg`   | Фон текста, выделенного пользователем |
| `--text-selection-text` | Цвет текста внутри этого выделения    |

Применение в глобальном слое стилей:

```scss
::selection {
  color: var(--text-selection-text);
  background-color: var(--text-selection-bg);
}
```

`::selection` оформляет браузерное выделение фрагмента текста; эта операция не равнозначна выбору опции или строки приложения. [^selection]

У пары нет `hover`, `pressed` и `disabled`: компоненты не управляют ею как последовательностью состояний кнопки.

Её значения не обязаны ссылаться на `selection-fill` или `accent-fill`. Совпадение цветов допустимо, но тема должна иметь возможность изменить браузерное выделение отдельно.

Нужно проверять выделение обычного текста, ссылок и текста внутри `<mark>`, особенно когда для них существуют локальные правила `::selection`.

## 6. Подсветка содержимого: `--highlight-*`

**Назначение:** выделить фрагмент из-за его релевантности текущему контексту.

Типичные случаи — найденное совпадение и текст, отмеченный приложением через `<mark>`. По HTML-семантике `<mark>` обозначает контекстную релевантность, а не является универсальной заменой `<strong>` для важного текста. [^mark]

### Обычная подсветка

| Токен                | Назначение                                 |
| -------------------- | ------------------------------------------ |
| `--highlight-bg`     | Подложка релевантного фрагмента            |
| `--highlight-text`   | Текст на этой подложке                     |
| `--highlight-border` | Граница или подчёркивающая линия подсветки |

Базовая подсветка может использовать только фон и текст. Токен границы не обязывает рисовать рамку вокруг каждого совпадения.

### Текущее совпадение

| Токен                        | Назначение                                      |
| ---------------------------- | ----------------------------------------------- |
| `--highlight-bg-current`     | Фон текущего совпадения при поисковой навигации |
| `--highlight-text-current`   | Текст текущего совпадения                       |
| `--highlight-border-current` | Контур или линия текущего совпадения            |

Например, при поиске найдено двенадцать совпадений. Все подсвечены базовой тройкой, а совпадение, на котором остановилась навигация «Следующее / Предыдущее», — тройкой `current`.

**`current` не означает `hover`, `pressed`, выбранность строки или DOM-фокус.** Кнопка «Следующее совпадение» может сохранять фокус, пока текущее совпадение меняется в документе.

```scss
.searchMatch {
  color: var(--highlight-text);
  background-color: var(--highlight-bg);
  box-shadow: inset 0 -1px 0 var(--highlight-border);

  &[data-current="true"] {
    color: var(--highlight-text-current);
    background-color: var(--highlight-bg-current);
    box-shadow: inset 0 -2px 0 var(--highlight-border-current);
  }
}
```

Здесь `data-current` — внутренний атрибут примера, не стандартный механизм управления поиском. Состояние и переходы между совпадениями задаёт компонент.

Для текущего совпадения полезно дополнительное различие, не ограниченное оттенком: заметная линия, рамка, маркер и доступное сообщение о позиции, например «Совпадение 3 из 12». Значимую информацию нельзя передавать только различием цветов. [^color]

## 7. Правила сочетания состояний

### Базовая роль и временная реакция

Сначала определяется сохраняющееся состояние и вариант оформления: нейтральный, акцентный, выбранный с мягкой подложкой или выбранный с насыщенной заливкой.

После этого **внутри выбранного семейства** применяется приоритет:

```text
disabled → pressed → hover → базовое состояние
```

Это приоритет выбора цветов, а не универсальный порядок всех CSS-правил. При одновременных `hover` и `pressed` используются pressed-значения. При недоступности временные hover/pressed-цвета не применяются.

Фокус рисуется отдельно и не входит в эту последовательность. `highlight-current` также относится к содержимому, а не к этой последовательности взаимодействия.

| Ситуация                                      | Оформление                                        |
| --------------------------------------------- | ------------------------------------------------- |
| Невыбранная нейтральная строка под указателем | `bg-hover` и обычный текст                        |
| Выбранная строка под указателем               | `selection-*-hover`                               |
| Выбранная строка в процессе нажатия           | `selection-*-pressed`                             |
| Выбранная недоступная строка                  | `selection-*-disabled`                            |
| Выбранная строка с видимым фокусом            | Цвета выбранности и отдельный `focus-ring`        |
| Совпадение внутри выбранной строки            | `highlight-*` у фрагмента, `selection-*` у строки |

### Нажатие не равно включённости

`pressed` в именах токенов обозначает кратковременное нажатие; типичный CSS-триггер — `:active`. [^selectors]

У кнопки-переключателя `aria-pressed="true"` обозначает сохраняющееся включённое состояние. В этом контракте оно может оформляться через `selection-*`, а физическое нажатие на уже включённую кнопку — через `selection-*-pressed`. [^button]

### Недоступность и фокус

Цвета не блокируют взаимодействие. Для нативных контролов применяется `disabled`; для компонентов с `aria-disabled="true"` блокировку команд необходимо обеспечить в реализации. [^disabled] [^aria]

Недоступный элемент иногда остаётся доступным для фокусирования, например внутри составного виджета. В таком случае видимый фокус сохраняется, хотя hover/pressed-оформление и активация отключены. [^keyboard]

`readonly` не следует автоматически приравнивать к `disabled`: это отдельное ограничение редактирования, а не универсальная недоступность контрола. [^readonly]

## 8. Пример: акцентная кнопка

Пример предназначен для нативного `<button>`; недоступность задаётся атрибутом `disabled`. Стили не назначают команде приоритет в приложении; они задают акцентный залитый вариант.

```scss
.accentButton {
  font: inherit;
  color: var(--accent-on-fill);
  background-color: var(--accent-fill);
  border: var(--border-width) solid var(--accent-border);
  border-radius: var(--radius-sm);
  padding: var(--space-sm) var(--space-md);

  @media (hover: hover) {
    &:enabled:hover {
      background-color: var(--accent-fill-hover);
      border-color: var(--accent-border-hover);
    }
  }

  &:enabled:active {
    background-color: var(--accent-fill-pressed);
    border-color: var(--accent-border-pressed);
  }

  &:disabled {
    color: var(--text-disabled);
    background-color: var(--bg-disabled);
    border-color: var(--border-interactive-disabled);
  }

  &:focus-visible {
    outline: var(--focus-width) solid var(--focus-ring);
    outline-offset: var(--focus-offset);
  }
}
```

Медиаусловие `hover: hover` ограничивает hover-оформление устройствами, чей основной указатель поддерживает удобное наведение. Это выбранная стратегия примера, а не механизм определения всех подключённых устройств ввода. [^hover]

Цвет текста остаётся `accent-on-fill` при обычном состоянии, наведении и нажатии. В недоступном состоянии применяется нейтральная пара. Геометрия фокуса проверяется отдельно, особенно при отрицательном отступе.

## 9. Требования к теме

### Полнота и независимость ролей

Тема должна предоставлять значения для всех 45 токенов этой группы, непосредственно или через документированное наследование базовой темы. Даже когда компонент использует только часть состояний, общий контракт остаётся доступным остальным компонентам.

Совпадающие значения разрешены. Роли не должны неявно связываться только ради устранения одинаковых HEX-значений. Особенно важно независимо настраивать функциональный фокус, декоративную линию, выбранность и пользовательское выделение текста.

Состояния задаются явно. Компонентам не следует вычислять hover/pressed через произвольное затемнение, прозрачность или `filter: brightness()`: это меняет согласованную темой пару фона и содержимого.

### Контрастные пары

| Передний план                         | С чем проверяется                                                  |
| ------------------------------------- | ------------------------------------------------------------------ |
| `accent-text` и его состояния         | Все обычные поверхности, на которых компонент их применяет         |
| `accent-on-fill`                      | `accent-fill`, `accent-fill-hover`, `accent-fill-pressed`          |
| `selection-text` и его состояния      | Соответствующие `selection-bg` по состоянию                        |
| `selection-on-fill`                   | `selection-fill`, `selection-fill-hover`, `selection-fill-pressed` |
| `selection-on-fill-disabled`          | `selection-fill-disabled`                                          |
| `text-selection-text`                 | `text-selection-bg`                                                |
| `highlight-text`                      | `highlight-bg`                                                     |
| `highlight-text-current`              | `highlight-bg-current`                                             |
| Функциональные контуры и `focus-ring` | Цвета, с которыми они непосредственно соседствуют                  |

Для обычного текста ориентир WCAG AA — минимум **4,5:1**; для крупного текста по определению WCAG — **3:1**. Для недоступных компонентов предусмотрены исключения, но сохранение читаемости остаётся задачей дизайна. [^contrast]

Для нетекстовых признаков, необходимых для распознавания компонента или состояния, применяется требование **3:1** к соседним цветам. Это не требование к каждому декоративному разделителю. Если слабая рамка — единственный признак существования поля, её нельзя считать чисто декоративной. [^nontext]

Тема проверяется не только по образцам цветов, но и на фактических поверхностях, во вложенных компонентах и сочетаниях состояний. Подобранные значения сами по себе не гарантируют доступность всех возможных композиций.

### Повышенная контрастность

Вариант повышенной контрастности сохраняет назначения токенов, но может менять их значения независимо. Декоративная линия не обязана повторять цвет функционального фокуса.

Системный режим `forced-colors` может заменять авторские цвета и отключать тени. Поэтому единственный функциональный индикатор нельзя оставлять исключительно в `box-shadow`; компонентам нужна проверка и подходящая альтернатива, например граница или outline с системным цветом. Не следует без необходимости отключать системную адаптацию через `forced-color-adjust: none`. [^forced]

## 10. Проверка компонента

Перед включением компонента в библиотеку проверяются поддерживаемые состояния и их сочетания. Минимальный набор: базовое, hover, pressed, disabled, выбранность, выбранность с hover/pressed/disabled, видимый фокус поверх применимых состояний.

Для текстовых компонентов дополнительно проверяются обычная подсветка, текущее совпадение и пользовательское выделение поверх них.

Проверка охватывает светлую, тёмную и контрастную темы; поверхности, заявленные компонентом; клавиатурную навигацию и отсутствие hover как обязательного условия использования.

**Итоговое правило: токен выбирается по смыслу оформляемой части, а не по понравившемуся оттенку. Совпадение цвета допустимо; смешение ролей — нет.**

## 11. Статусные цвета

Для каждого из `success`, `warning`, `error`, `info` предусмотрено восемь независимых ролей:

| Роль | Назначение |
| --- | --- |
| `--<status>-text` | Текст, одноцветные иконки и рамка мягкого статусного элемента |
| `--<status>-bg` | Мягкая подложка outline/soft |
| `--<status>-bg-hover` | Её фон при наведении |
| `--<status>-bg-pressed` | Её фон во время нажатия |
| `--<status>-fill` | Насыщенная заливка solid |
| `--<status>-fill-hover` | Её фон при наведении |
| `--<status>-fill-pressed` | Её фон во время нажатия |
| `--<status>-on-fill` | Содержимое на насыщенной заливке во всех трёх состояниях |

В мягком варианте цвет текста и рамки совпадает и остаётся `--<status>-text` при наведении и нажатии. Меняется только подложка. Для solid постоянным остаётся `--<status>-on-fill`, а меняется только заливка. `text` нельзя применять как содержимое на `fill`, а `on-fill` — как текст на `bg`.

Тема проверяет постоянный `text` на всех трёх мягких фонах, а постоянный `on-fill` — на всех трёх насыщенных заливках. Состояния задаются явно; произвольный `color-mix`, затемнение или прозрачность не заменяют эти пары. Старые имена `--<status>-hover` и `--<status>-pressed` больше не входят в контракт.

Нестатусный акцент использует `--accent-*` и может менять текст и границу по своим отдельным состояниям. `brand` удалён из тонов и цветовых вариантов текста; сохраняющийся выбор по-прежнему оформляется через `--selection-*`.

У статусной семьи нет собственных disabled-токенов: недоступный контрол использует нейтральные `text-disabled`, `bg-disabled` и `border-interactive-disabled`. Для ghost фон и граница могут оставаться прозрачными. Ошибка поля относится к мягкой паре `error-bg` / `error-text`, состояние disabled имеет приоритет, фокус рисуется отдельно.
