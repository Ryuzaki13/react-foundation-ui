# Плавающие окна

`FloatingWindows` создаёт независимую рабочую область для немодальных окон.
`FloatingWindow` размещает внутри неё произвольный React-контент и предоставляет
перемещение, порядок наложения и необязательное закрытие.

## Подключение

```tsx
import { FloatingWindow, FloatingWindows } from "@ryuzaki13/react-foundation-ui/floating-windows";
import "@ryuzaki13/react-foundation-ui/styles.css";

export function NotesArea() {
	return (
		<FloatingWindows style={{ height: "min(70dvh, 36rem)" }}>
			<FloatingWindow id="notes" title="Заметки" width="24rem" height="20rem">
				<p>Любое содержимое приложения.</p>
			</FloatingWindow>
		</FloatingWindows>
	);
}
```

Готовый CSS с локальными классами компонентов подключается один раз в
host-приложении. Sass API настраивает foundation-токены и utility-классы,
но не заменяет компонентные CSS Modules из `styles.css`. Если host уже
подключил этот CSS, повторный импорт не нужен. Настройка токенов и тем описана
в [README пакета](../../README.md#подключение-стилей).

## Область и размеры

Область по умолчанию занимает `100%` ширины и высоты родителя. Абсолютно
позиционированные окна не формируют её высоту: задайте высоту области через
`style`/`className` либо обеспечьте определённую высоту родителя. Окно измеряется
в CSS-пикселях относительно этой области.

`width` и `height` задают желаемый размер окна. Максимальный размер ограничен
областью; содержимое прокручивается внутри окна. Положение ограничивается так,
чтобы окно полностью помещалось в область. `ResizeObserver` отслеживает
фактический размер области и окна, поэтому изменение размеров родителя,
содержимого или CSS также приводит к проверке координат. Пока размер ещё не
известен или область скрыта и имеет нулевой размер, координаты не сбрасываются.

Для слоя поверх страницы приложение может задать области
`style={{ position: "fixed", inset: 0 }}` и выбрать её общий `z-index`.
Встроенного portal нет: место в DOM, stacking context страницы и взаимодействие
с другими overlay принадлежат приложению. Пустая часть области пропускает
pointer-события; сами окна остаются интерактивными.

## Public API

Subpath экспортирует `FloatingWindows`, `FloatingWindow` и типы
`FloatingWindowsProps`, `FloatingWindowProps`, `FloatingWindowPosition`.
Объектные контракты неизменяемы (`Readonly`). Обязательные props области —
`children`; обязательные props окна — `id`, `title` и `children`. Остальные
props необязательны.

### `FloatingWindows`

| Prop             | Тип                        | Назначение                                                                                                                                                             |
| ---------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `children`       | `ReactNode`                | Содержимое области, включая `FloatingWindow`.                                                                                                                          |
| `className`      | `string`                   | Класс корневой области.                                                                                                                                                |
| `style`          | `CSSProperties`            | Размер и размещение области.                                                                                                                                           |
| `storageKey`     | `string`                   | Явное включение сохранения координат под отдельным ключом `localStorage`. Пустой ключ недопустим.                                                                      |
| `cascadeOffset`  | `number`                   | Шаг разведения совпадающих начальных координат в CSS-пикселях; по умолчанию `24`. Конечное неотрицательное число; `0` отключает каскад. Читается при создании области. |
| `onStorageError` | `(error: unknown) => void` | Необязательная диагностика ошибки чтения, проверки или записи сохранённых координат.                                                                                   |

Смена `storageKey` пересоздаёт область вместе с дочерним React-деревом. Для смены
начальных настроек, включая `cascadeOffset`, используйте новый React `key`.
Дочерние элементы не клонируются и не анализируются по типу компонента.

### `FloatingWindow`

| Prop               | Тип                                          | Назначение                                                                                                      |
| ------------------ | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `id`               | `string`                                     | Стабильный непустой ID, уникальный среди одновременно открытых окон одной области.                              |
| `title`            | `string`                                     | Видимый заголовок и доступное имя окна.                                                                         |
| `children`         | `ReactNode`                                  | Содержимое прокручиваемой части окна.                                                                           |
| `defaultPosition`  | `FloatingWindowPosition`                     | Начальная позиция; по умолчанию `{ x: 24, y: 24 }`. Это начальное значение, а не controlled prop.               |
| `width`            | `CSSProperties["width"]`                     | Желаемая ширина; по умолчанию `360` CSS-пикселей. Ограничивается шириной области.                               |
| `height`           | `CSSProperties["height"]`                    | Желаемая высота; по умолчанию `300` CSS-пикселей. Ограничивается высотой области.                               |
| `actions`          | `ReactNode`                                  | Дополнительные действия в заголовке вне кнопки перемещения.                                                     |
| `onClose`          | `() => void`                                 | Запрос закрытия. При наличии callback появляется кнопка закрытия. Удаление окна из дерева выполняет приложение. |
| `onPositionChange` | `(position: FloatingWindowPosition) => void` | Вызывается один раз после завершённого пользовательского перемещения, только если координаты изменились.        |
| `className`        | `string`                                     | Класс панели окна.                                                                                              |

```ts
type FloatingWindowPosition = Readonly<{ x: number; y: number }>;
```

Обе координаты должны быть конечными числами. ID содержит хотя бы один
непробельный символ и не превышает 256 символов. Одинаковые ID разрешены в разных
областях. `FloatingWindow` требует окружающий `FloatingWindows`; два открытых
окна с одним ID внутри одной области считаются ошибкой контракта. При смене
смыслового ID задавайте также React `key={id}`.

Начальная позиция выбирается в таком порядке: известная области позиция ID,
затем `defaultPosition`, затем каскад при совпадении начальных координат с уже
открытым окном. Каскад разводит начальные точки; перекрытие окон после ограничения
границами области допускается.

`onPositionChange` не вызывается для отмены, перемещения без изменения координат,
ограничения позиции при resize или восстановления из storage. Это уведомление
о завершённом действии пользователя, а не controlled position API.

## Управление и фокус

Перемещение указателем начинается только на кнопке перемещения в заголовке.
Поля ввода, выделение текста, прокрутка и дополнительные действия не являются
drag-handle. Окно поднимается при взаимодействии указателем или получении фокуса.
При `pointercancel`, потере pointer capture, потере фокуса или изменении
измеренной геометрии незавершённое перемещение отменяется. Отмена не вызывает
`onPositionChange` и не сохраняет промежуточные координаты.

Клавиатура на кнопке перемещения:

| Клавиши                 | Действие                                                          |
| ----------------------- | ----------------------------------------------------------------- |
| `Space` или `Enter`     | Начать перемещение; повторное нажатие завершает его.              |
| Стрелки                 | Во время перемещения сдвинуть окно на `10` CSS-пикселей.          |
| `Shift` + стрелки       | Во время перемещения сдвинуть окно на `1` CSS-пиксель.            |
| `Escape`                | Отменить текущее перемещение с возвратом в начальную точку.       |
| `Tab` или потеря фокуса | Отменить клавиатурное перемещение и продолжить обычную навигацию. |

Вне режима перемещения `Escape`, всплывший из верхнего окна с фокусом внутри,
запрашивает его закрытие при наличии `onClose`. Вложенный контрол может сначала
обработать собственный `Escape`; окно не должно закрываться вместо такого
локального действия. Для окна без `onClose` закрытие не предлагается.

Панель имеет `role="dialog"`, имя через `aria-labelledby` и `tabIndex={-1}`.
После открытия она получает программный фокус через общий `useOverlayFocus`.
При удалении окна фокус возвращается ранее активному элементу, если он ещё
подключён к документу; если фокус уже находится в другом окне или на странице,
он сохраняется там. Приложение управляет моментом появления окна и доступностью
инициатора для возврата фокуса.

Окна немодальные: без блокировки страницы, focus trap и глобальных клавиатурных
перехватчиков. Их нельзя использовать как замену модальному подтверждению,
требующему блокировки фоновых действий.

## Состояние и ответственность

| Владелец                       | Состояние и действия                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- |
| Приложение                     | Состав открытых окон, их ID, контент, черновики, бизнес-действия и решение удалить окно после `onClose`. |
| Одна область `FloatingWindows` | Координаты, измеренные размеры, порядок наложения и последние позиции закрытых окон.                     |
| Конкретное окно                | DOM-измерение, локальное перемещение указателем/клавиатурой, фокус и callbacks.                          |

Состояние области создаётся отдельно для каждого экземпляра. Закрытие окна
удаляет его из текущего порядка наложения, но сохраняет последнюю позицию ID на
время жизни области. Поэтому повторное открытие возвращает окно в известную
позицию. Черновики переживают закрытие только тогда, когда приложение хранит их
за пределами размонтируемого содержимого окна.

Геометрическая модель не зависит от DOM, React или `localStorage`. UI измеряет
элементы и передаёт размеры модели; модель ограничивает координаты и сохраняет
identity неизменённых окон. React-подписка конкретного окна получает только его
snapshot: перемещение одного окна не требует подписывать соседнее содержимое
на все координаты. Порядок слоёв локален и нормализуется внутри области.

Во время перемещения `requestAnimationFrame` обновляет только DOM-preview
активной панели. Промежуточные кадры не меняют store и не записываются в
`localStorage`; конечная позиция фиксируется по завершении действия. Изменение
геометрии отменяет текущий preview и применяет актуальные ограничения области.

Resize, minimize, maximize, привязка к краям, список открытых окон и серверное
хранение раскладки не входят в этот API.

## Сохранение координат

Без `storageKey` компонент не читает и не пишет browser storage. При его наличии
сохраняются только ID и последние координаты. Контент, поля ввода, размеры,
состав открытых окон и активный порядок не сохраняются. Приложение выбирает ключ
с учётом пользователя и назначения области; разные одновременно работающие
области должны использовать разные ключи. Синхронизации между вкладками нет.

Сохраняется не более 200 последних по порядку регистрации ID и 65 536 символов
JSON; при превышении лимита старые записи исключаются из сохраняемого снимка.
Сохранённые данные проверяются на границе чтения. Неизвестная версия,
повреждённый JSON, повторяющиеся/пустые ID и нечисловые/бесконечные координаты
отклоняются целиком. Старые форматы не мигрируются. Для этого неавторитетного
кэша можно удалить именно выбранный ключ и пересоздать область, как в story
«Сохранение координат».

После ошибки чтения сохранение отключается до пересоздания области. После
ошибки записи дальнейшие записи также прекращаются до пересоздания. Окна
продолжают работать в памяти; `onStorageError` позволяет приложению сообщить о
недоступности сохранения или передать диагностику. Без callback отдельного
уведомления нет. Восстановленные координаты повторно ограничиваются фактическим
размером текущей области.

## SSR и проверка в браузере

Первичный render не читает `window`, `document` и `localStorage`; восстановление
координат выполняется после hydration. SSR и первая клиентская разметка используют
одинаковые начальные props. Не подставляйте в них browser-only значения во время
render; допускается корректировка положения после измерения и чтения storage.
Для числовых размеров начальная разметка уже ограничивает позицию CSS-выражением.
Для строковых размеров (включая `auto`, `%` и `rem`) соответствующая ось до
DOM-измерения начинается с нуля; затем применяется заданная начальная позиция.

Для функциональных проверок предусмотрены атрибуты `data-floating-windows` у
области, `data-floating-window-id` у панели и
`data-floating-window-action="move"` у кнопки перемещения. CSS Modules и текст
заголовка не служат идентификаторами окна.

Stories находятся в [stories/FloatingWindows.stories.tsx](stories/FloatingWindows.stories.tsx):

- `InteractiveWindows` — ввод, действия в заголовке, закрытие и повторное открытие;
- `NarrowHost` — ограничение больших размеров окна и прокрутка длинного контента;
- `IndependentHosts` — одинаковые ID в независимых областях;
- `PersistedPositions` — восстановление и явный сброс только ключа примера.

При проверке интеграции используйте светлую и тёмную темы, узкую область,
изменение её размера, pointer cancel, клавиатурную отмену и работу интерактивного
содержимого. Успешная сборка сама по себе не подтверждает эти сценарии.
