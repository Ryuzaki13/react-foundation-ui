<Subtitle>Типобезопасный getter-based мультиселект для произвольных option</Subtitle>

`MultiSelect<TOption>` сохраняет исходный тип option на всём пути от `options` и `value` до `onChange`.
Компонент не требует `CollectionItem` и независимо получает identity, основной текст, отображаемый код, группу и поисковое представление.

## Основной сценарий

<Primary />

<Controls of={MultiSelectStories.IndependentIdentity} />

```tsx
import { useState } from "react";

import { MultiSelect } from "@ryuzaki13/react-foundation-ui/multi-select";

type DepartmentOption = {
	id: string;
	name: string;
	displayCode: string;
};

const options: DepartmentOption[] = [
	{ id: "education:north", name: "Учебное отделение «Север»", displayCode: "УО-01" },
	{ id: "education:south", name: "Учебное отделение «Юг»", displayCode: "УО-01" }
];

export function Example() {
	const [value, setValue] = useState<DepartmentOption[]>([]);

	return (
		<MultiSelect
			label="Подразделения"
			options={options}
			value={value}
			onChange={setValue}
			getOptionKey={(option) => option.id}
			getOptionLabel={(option) => option.name}
			getOptionCode={(option) => option.displayCode}
		/>
	);
}
```

## Контракт selector-функций

- `getOptionKey` задаёт единственный identity option. Строковый ключ должен быть уникальным и устойчивым; числовой domain-id следует явно преобразовать через `String(id)`.
- `getOptionLabel` возвращает основной текст, а `getOptionCode` — независимый дополнительный код. Одинаковый отображаемый code не объединяет option, если их key различаются.
- По умолчанию поиск учитывает label, code и текст заголовка группы. `getOptionSearchText` полностью заменяет это представление и подходит для скрытых синонимов, транслитерации или заранее нормализованного индекса.
- `getOptionGroup` объединяет соседние option с одинаковым `group.key`. Выбранная и доступная секции группируются независимо, поэтому один заголовок может появиться в обеих секциях.

## Draft и commit

При открытии компонент создаёт draft из контролируемого `value`. Checkbox изменяет draft, не вызывая `onChange` немедленно; закрытие popup подтверждает его через `onChange` и передаёт то же значение в `onClose`.
Кнопка с названием option выбирает только эту option и сразу закрывает popup. `getOptionDisabled` получает `selectedOptions` и `selectedKeys` текущего draft, а также `committedSelectedOptions`, поэтому взаимозависимые ограничения обновляются ещё до commit.

`renderToken` и `renderToolbar` получают тот же текущий выбор: draft, пока popup открыт, и подтверждённое значение после закрытия.

## Сценарии использования

### Identity независимо от отображаемого code

У двух option намеренно одинаковый `code`, но разные `id`. Их можно выбирать независимо без преобразования в `CollectionItem`.

<Canvas of={MultiSelectStories.IndependentIdentity} />

### Группировка и selected-first

Подтверждённые option отображаются первыми. После них идёт доступная секция; внутри обеих секций соседние option группируются отдельно.

<Canvas of={MultiSelectStories.GroupedSelectedFirst} />

### Контекстная блокировка и поисковый индекс

Option «Все подразделения» взаимоисключается с частным выбором через draft-aware `getOptionDisabled`.
`getOptionSearchText` добавляет невидимые поисковые синонимы: например, запрос `СПО` находит оба учебных отделения.

<Canvas of={MultiSelectStories.ContextualDisabledAndSearch} />

### Обязательное поле и ошибка значения

`required` отмечает поле и задаёт `aria-required` для combobox. `fieldError` выводит ошибку выбора под полем; существующий `error` продолжает описывать ошибку получения опций внутри popup. Проверку массива выбранных значений выполняет форма.

## Миграция с DeprecatedMultiSelect

`DeprecatedMultiSelect` сохраняет `CollectionItem` и OData-ориентированный `codeKey`/`textKey` API. Для перехода на канонический `MultiSelect` замените:

- `items` на `options`;
- `codeKey` на `getOptionKey`;
- `textKey` на `getOptionLabel`;
- использование identity как видимого code на отдельный `getOptionCode`;
- `renderItem`, если он только вычислял text/code, на `getOptionLabel` и `getOptionCode`; сложную структурированную пару можно вернуть через `renderOption`.

`onChange` после миграции получает `TOption[]`, поэтому адаптер к `CollectionItem` больше не нужен. `ODataMultiSelect` продолжает использовать `DeprecatedMultiSelect` внутри пакета.

Старый контракт с `codeKey`/`items` доступен через `DeprecatedMultiSelect`; новый код должен использовать selector API `MultiSelect`.
