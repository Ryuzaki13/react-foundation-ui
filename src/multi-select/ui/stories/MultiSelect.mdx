MultiSelect сохраняет совместимый `codeKey`/`textKey` API для существующих consumers и OData-обёрток; компонент не объявлен deprecated.
Для нового кода с произвольной типизированной option, независимыми identity и отображаемым code предпочтителен `OptionMultiSelect` из того же package subpath.
MultiSelect уже имеет живые stories, а эта страница собирает их в структурированную документацию с краткими рекомендациями, примерами подключения и API.
Ниже можно быстро проверить базовый сценарий, а затем перейти к отдельным режимам использования и состояниям компонента. Отдельно разобраны загрузку, ошибочные состояния.

## Основной сценарий

<Controls of={MultiSelectStories.Basic} />

```tsx
import { useState } from "react";

import { MultiSelect } from "@ryuzaki13/react-foundation-ui/multi-select";

const items = [
	{ code: "MOW", label: "Москва" },
	{ code: "EKB", label: "Екатеринбург" }
];

export function Example() {
	const [value, setValue] = useState([]);
	const [query, setQuery] = useState("");

	return (
		<MultiSelect
			label="Города"
			items={items}
			value={value}
			query={query}
			onQuery={setQuery}
			onChange={setValue}
			codeKey="code"
			textKey="label"
		/>
	);
}
```

## Практические рекомендации

- Для асинхронных сценариев предусмотрите не только успешный путь, но и загрузку, пустой результат и ошибку.
- Popup использует `grid`, потому что строка содержит два самостоятельных действия: checkbox меняет черновой множественный выбор, а кнопка с названием выбирает только текущую строку и сразу применяет значение.
- При фокусе в поле стрелки перемещают активную строку, `Ctrl+Space` переключает её checkbox без закрытия, а `Enter` выполняет немедленный выбор только активной строки.
- Массовые действия находятся вне `grid`, поэтому остаются самостоятельными кнопками и не нарушают структуру составного виджета.
