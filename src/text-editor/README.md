# Редактор и просмотр Lexical-документа

## Редактор и профиль панели

`TextEditorLexical` из `@ryuzaki13/react-foundation-ui/text-editor` создаёт
интерактивный редактор только в браузере. `initialData` задаёт начальный
документ: существующий `TextEditorLexicalRaw` имеет приоритет над `html`.
`onChange` сообщает новый `{ html, raw }`; consumer владеет черновиком,
валидацией и сохранением. `initialData` не является controlled value:
не следует возвращать в него каждое изменение только ради синхронизации
родительского state.

`toolbarComponents` позволяет включать группы действий. История и очистка
semantic tag сохраняют значение `true` по умолчанию; группы `blocks`,
`inline`, `alignment`, `links` и `tags` включаются явно. Новые необязательные
настройки не изменяют существующий профиль:

- `blockStyles` ограничивает стили в включённой группе `blocks`;
- `linkTypes` ограничивает виды в включённой группе `links`;
- отсутствие списка оставляет все прежние действия группы, пустой список
  скрывает её;
- списки выбирают подмножество уже существующих controls, не добавляют новые
  стили и не меняют канонический порядок; повторяющиеся значения не создают
  дополнительные кнопки;
- `clearSemanticTag: false` отдельно убирает очистку semantic tag;
- `externalLinkOptions.allowQrCode: false` отключает предложение QR в диалоге
  внешней ссылки и при подтверждении выставляет `qrCode: false`, даже если
  редактируемая ссылка содержала `true`; отсутствие настройки сохраняет
  прежнее поведение.

Например, предметно независимый профиль для абзацев, списков и внешних ссылок:

```tsx
import { LinkTypes, TextEditorLexical } from "@ryuzaki13/react-foundation-ui/text-editor";

<TextEditorLexical
	initialData={initialData}
	onChange={onChange}
	editableProps={{ "aria-label": "Редактируемый документ" }}
	toolbarComponents={{
		blocks: true,
		blockStyles: ["unstyled", "ordered-list-item", "unordered-list-item"],
		inline: true,
		links: true,
		linkTypes: [LinkTypes.LINK],
		alignment: false,
		tags: false,
		clearSemanticTag: false
	}}
	externalLinkOptions={{ allowQrCode: false }}
/>;
```

Это **профиль панели, а не sanitizer или валидатор документа**. Настройки не
удаляют узлы из `initialData`, не фильтруют вставку и не заменяют проверку raw
перед сохранением. Правила допустимого содержимого и доступ к данным остаются
у consumer; пакет не содержит правил конкретного приложения.

Новая подпись внешней ссылки наследует активные inline-format/style
восстановленного выделения. Это не гарантирует сохранение нескольких разных
text nodes и смешанного форматирования: текущая вставка создаёт одну подпись.

`editableProps` передаёт `id`, `aria-label`, `aria-labelledby`,
`aria-describedby`, `aria-invalid` и `aria-required` непосредственно в
contenteditable. Эти атрибуты связывают редактор с подписью и ошибкой
consumer, но не запускают валидацию. Для доступного имени задайте
`aria-label` или связь с видимой подписью через `aria-labelledby`.

Storybook `Text/TextEditorLexical` показывает реальную панель по умолчанию и
ограниченный профиль. Ввод не сопровождается повторным построением raw JSON
в интерфейсе: `onChange` доступен в панели действий Storybook.

### Компактное представление

`presentation="compact"` предназначен для встроенного короткого ввода:
внешняя рамка и её padding отсутствуют, editable растёт до ограничителя и затем
прокручивается внутри. Одна кнопка открывает прежние команды в немодальной
панели; touch-target кнопок не уменьшается. Режим одинаков на всех ширинах и
не использует browser viewport при render. `presentation="document"` и отсутствие
prop сохраняют обычную открытую панель и рамку.

`placeholder={null}` полностью исключает подсказку, в том числе её высоту.
Строка задаёт собственный текст, отсутствие prop оставляет стандартное
«Введите текст». Доступное имя по-прежнему задаётся через `editableProps`,
а не через placeholder.

Snapshot выделения принадлежит одной сессии панели. Открытие/отмена не меняет
документ; команда восстанавливает исходное выделение перед применением.
Обычная команда возвращает фокус в editable, команда ссылки передаёт его
диалогу. Настройки панели, сериализация и validation consumer не меняются.
Представление не фиксирует route-height, не блокирует document-scroll и не
управляет экранной клавиатурой: это ответственность внешнего viewport/shell.

### Доступность ввода и очистка

`readOnly?: boolean` по умолчанию равен `false`. Значение `true` запрещает
пользовательский ввод и команды панели, включая undo/redo, и отзывает открытые
сессии форматирования и диалогов. Текущий документ и история сохраняются:
после возврата `false` можно продолжить работу. Это UI-режим, а не проверка
прав доступа и не серверная валидация. Переключение contenteditable может
закрыть экранную клавиатуру; пакет не обещает сохранение клавиатуры на iOS.

`ref?: Ref<TextEditorHandle>` предоставляет только `clear(): void`. Метод
заменяет документ одним пустым абзацем и сбрасывает undo/redo без remount
редактора. `onChange` сообщает пустой HTML/raw обычным контрактом. После
очистки новый ввод начинает новую историю: отмена не возвращает старый текст.
`clear()` разрешён также при `readOnly`, например после подтверждённого
сохранения consumer. Метод не возвращает `initialData` и не является reset
к исходному документу; изменение `initialData` после mount также не заменяет
редактируемый документ. Для другого документа consumer создаёт новую сессию
с соответствующим React key.

```tsx
import { useRef } from "react";
import { type TextEditorHandle, TextEditorLexical } from "@ryuzaki13/react-foundation-ui/text-editor";

const editorRef = useRef<TextEditorHandle>(null);

<TextEditorLexical ref={editorRef} readOnly={isSaving} initialData={initialData} onChange={onChange} />;
// После подтверждённого результата текущего сохранения:
editorRef.current?.clear();
```

Очистка сохраняет фокус, если он уже внутри редактора, и не забирает его у
внешнего элемента. Незавершённые команды/диалоги и отложенный возврат фокуса
отзываются. Сохранённый старый handle после замены ref или unmount не действует.
Отмена обычного диалога, напротив, восстанавливает исходное выделение и фокус
без изменения текста. Транспорт, pending/error/retry и решение, к какому
черновику относится ответ сервера, остаются ответственностью consumer.

Storybook содержит обычный и компактный lifecycle-примеры. Behavioral tests
проверяют идентичность DOM, history barrier, readOnly, focus и устаревшие
callbacks; они не заменяют проверку физической экранной клавиатуры.

## Просмотр Lexical-документа

`TextEditorLexicalViewer` — предметно независимый компонент чтения из
`@ryuzaki13/react-foundation-ui/text-editor`. Принимает `raw` существующего
формата `TextEditorLexicalRaw`, необязательные `className` и `fallback`.
`fallback` по умолчанию сообщает, что содержимое не поддерживается.

### Паспорт реализации

- Public boundary — существующий `/text-editor`, без изменения API редактора.
- Component — только безопасное React-представление; парсинг сериализованных
  узлов и ссылок принадлежит приватному `lib/viewer`, типы проекции — `model`.
- SSR и браузер строят одинаковое семантическое дерево без DOM API, editor
  instance, contenteditable, effects, subscriptions и HTML injection.
- `raw` считается immutable snapshot. Чистая проекция мемоизируется по его
  ссылке; изменение данных передаётся новым объектом. Server/Query state,
  права пользователя, persistence и загрузка данных принадлежат consumer.
- Произвольные атрибуты, HTML и CSS из документа не переносятся в DOM.
  Неизвестный или повреждённый документ целиком заменяется `fallback`,
  без частичного скрытия неизвестных узлов и без логирования содержимого.

### Область первого viewer

Поддерживаются абзацы, заголовки h1–h6, цитаты, маркированные и нумерованные
списки с вложениями, переносы строк и текст. Inline formatting: жирный,
курсив, подчёркивание, зачёркивание, код, выделение, нижний и верхний индексы.
Учитываются направление текста, стандартное выравнивание и отступ элементов.
Визуальный отступ ограничен четвертью ширины области, чтобы глубокий indent
не вытеснял текст за границу узкого consumer.
Нумерация сохраняет `start` списка и `value` пунктов; обёртка вложенного
списка не рисует лишний маркер.

Узлы `link` и `accessible-link` показывают только абсолютные HTTP/HTTPS
ссылки без credentials. `target` ограничен `_self`/`_blank`; у новой вкладки
всегда `rel="noopener noreferrer"`. Небезопасный URL делает документ
неподдержанным. Не выполняются запросы, переходы или автоматическая загрузка
ресурсов. Относительные, mailto/tel и бизнес-ссылки, QR, semantic-tag,
произвольный CSS, checklist, изображения и неизвестные nodes в первый API
не входят; их нельзя считать поддержанными только из-за принятого envelope.

Технические пределы: 10 000 узлов, глубина 32, суммарно 1 000 000 UTF-16
единиц поддерживаемых строк и indent от 0 до 32. Они защищают renderer от
чрезмерного дерева, но не заменяют
правила сохранения конкретного приложения. Viewer не ограничивает длину
сообщения по бизнес-правилам и не является валидатором записи в БД.
Вход — сериализованные plain JSON objects и плотные массивы; getter,
нестандартные prototypes и произвольные JavaScript objects не входят в API.

### Проверки и доставка

Тесты проверяют parser, URL boundary, неподдержанные данные, сочетания
форматирования, вложенные списки, SSR/hydration и обновление props.
Storybook показывает форматирование, списки, ошибки и длинный текст в узкой
области; проверяются светлая и тёмная темы.

Добавление API совместимо с текущим major 3 и предназначено для minor-релиза.
Локальный source/commit не означает публикацию. Consumer подключает viewer
только после отдельного подтверждённого выпуска; локальная копия не нужна.
