`List` компонует `Toolbar`, `Content` или `VirtualizedContent` и `Footer`.
Владелец передаёт элементы и их представление: компонент не читает данные, не хранит копию источника и не знает предметных правил приложения.

## Панели действий в 3.24.0

`List.Toolbar` и `List.Footer` принимают только `children` (`PropsWithChildren`).
Каждая часть создаёт один нейтральный DOM-контейнер, в том числе без содержимого:
несколько действий панели не занимают отдельные строки родительской раскладки
`auto minmax(0, 1fr) auto` и не вытесняют viewport.

Панели не добавляют обязательные отступы, границы или раскладку действий.
Если они нужны, consumer передаёт внутри `children` собственный `FlexContainer`,
`GridContainer` или другой оформленный контент.

> Внимание: в **3.24.0** намеренно удалены `className` у `List.Toolbar`/`List.Footer`
> и type exports `ListToolbarProps`/`ListFooterProps`. Это согласованное изменение
> прежнего контракта: перенесите оформление во вложенный контейнер и удалите
> импорты этих типов. `List`, `List.Content` и `List.VirtualizedContent` сохраняют
> свои `className` props.

```tsx
<List.Toolbar>
	<FlexContainer wrap gap="sm" className="paddingSm borderBottom">
		<SearchControl />
		<FilterControl />
	</FlexContainer>
</List.Toolbar>
```

## Полный источник

Все элементы уже доступны в одном `readonly` массиве. Виртуализация ограничивает только DOM-окно, не набор данных; `hasNextPage` и фиктивный `fetchNextPage` не нужны.
Внешняя область должна иметь ограниченную высоту, иначе прокрутка не получает собственного viewport.

```tsx
import { List } from "@ryuzaki13/react-foundation-ui/list";

<List.VirtualizedContent
	items={items}
	getKey={(item) => item.id}
	render={(item) => <ItemRow item={item} />}
	estimateSize={120}
	overscan={5}
	aria-label="Список записей"
/>;
```

`getKey` должен возвращать уникальный устойчивый ключ записи, а не её текущий индекс.
Измеренные высоты принадлежат устойчивым ключам строк: изменение содержимого, перестановка и новые элементы не переносят старую высоту на другую строку.
`estimateSize` — начальная оценка высоты измеряемой строки в пикселях, не фиксированная высота записи. По умолчанию используются `120` и `overscan=5`.
Выбирайте оценку, близкую к реальному содержимому; после измерения действует фактическая высота.

`separated` рисует разделители между записями по их порядку в полном источнике,
а не по краю текущего DOM-окна. Последняя запись завершённого набора не получает
разделитель; при `hasNextPage=true` он остаётся перед следующей страницей.
Служебная строка загрузки собственного разделителя не имеет.
При нескольких колонках разделитель проходит между измеряемыми строками, а не между
ячейками; неполная последняя строка остаётся одной строкой. Заголовки групп собственного
разделителя не получают.

`onVisibleKeysChange(keys: readonly string[])` передаёт неизменяемый массив исходных ключей записей
из строк, хотя бы частично пересекающих viewport, в порядке отображения. При нескольких
колонках в результат входят все ячейки пересекающей viewport измеряемой строки, в том числе
при её вертикальном переносе на узкой ширине. Это интересы строки целиком, а не отдельная
проверка геометрии каждой ячейки. Дополнительные DOM-строки `overscan`, заголовки групп и
служебная строка постраничной загрузки в него не входят. Callback вызывается
только после commit, при изменении пересечения из-за scroll, resize, измерений или набора;
SSR и render не вызывают его и не читают геометрию строк.

Пустой источник либо viewport нулевой высоты передают `[]`. Повторное событие с той же
последовательностью ключей и той же функцией ничего не публикует. Сохраняйте identity
callback через `useCallback` или стабильный внешний порт: при замене consumer прежний
непустой диапазон закрывается `[]`, а новый получает текущие ключи. Удаление callback
или unmount тоже закрывает последний непустой диапазон единственным `[]`.
Это геометрический контракт списка, не гарантия видимости окна браузера: остановка
фоновых запросов и подписок при скрытии вкладки остаётся у consumer.

## Несколько колонок без групп

`Content` и `VirtualizedContent` принимают один и тот же `columns?: ListColumns`.
Consumer продолжает передавать плоские `items`, обычный `getKey` и представление одной
записи в `render`: List сам объединяет записи в строки максимум по `columns.count` ячеек.
Без `columns` сохраняется по одной записи в строке. `count` должен быть положительным
целым числом; некорректное значение вызывает `RangeError`.

```tsx
<List.Content
	items={items}
	getKey={(item) => item.id}
	render={(item) => <ItemCard item={item} />}
	columns={{ count: 3, minItemWidth: "16rem" }}
/>
```

Без `minItemWidth` строка использует заданное количество равных колонок.
`minItemWidth` принимает CSS-ширину и включает адаптивный перенос через
`repeat(auto-fit, minmax(min(100%, minItemWidth), 1fr))`: на узком экране ячейки одной
заранее собранной строки располагаются вертикально. Число исходных записей в этой строке
при resize остаётся прежним. Неполная последняя строка с `minItemWidth` растягивает
оставшиеся ячейки на доступную ширину.

## Необязательная группировка

`grouping?: ListGrouping<T>` работает независимо от `columns`: можно использовать только
группы, только колонки или обе настройки. `grouping.getKey(item, index)` получает запись
и её индекс в исходном `items`. Записи с одинаковым строковым ключом собираются в одну
группу, даже если не стояли рядом в источнике. Порядок групп задаёт первое появление ключа,
а порядок записей внутри каждой группы соответствует исходному массиву.

```tsx
<List.VirtualizedContent
	items={participants}
	getKey={(participant) => participant.id}
	render={(participant) => <ParticipantCard participant={participant} />}
	columns={{ count: 3, minItemWidth: "16rem" }}
	grouping={{
		getKey: (participant) => participant.departmentId,
		render: (groupKey, groupItems) => (
			<h3>
				{groupKey}: {groupItems.length}
			</h3>
		)
	}}
	estimateSize={240}
	overscan={3}
/>
```

`grouping.render(groupKey, items)` получает ключ и `readonly` массив всех исходных записей
группы. Заголовок занимает всю ширину, а следующая строка начинается внутри этой группы:
неполная строка не дополняется записями из соседней группы. Обычный `getKey(item, index)`
тоже получает исходный индекс, поэтому встроенные заголовки и перестроение строк его не сдвигают.

В виртуальном списке `estimateSize` и `overscan` относятся к измеряемым строкам, включая
строки заголовков, а не к отдельным ячейкам. При адаптивном переносе высота одной строки
может заметно вырасти. Все записи строки остаются единой единицей измерения и видимости;
`onVisibleKeysChange` продолжает возвращать исходные ключи записей.

Ключ ячейки сохраняется внутри её строки, но перестроение набора или изменение `count`
может переместить запись в другую строку и вызвать remount её содержимого. Долгоживущее
состояние выбора, редактирования или раскрытия храните у consumer по исходному ключу,
как состояние выбранной записи в примерах.

## Позиция при изменении набора

`preserveScrollAnchor=true` по умолчанию сохраняет исходный ключ первой записи видимой строки и смещение внутри строки.
Если эта запись исчезла, выбирается ближайший оставшийся ключ в прежнем порядке; при равном расстоянии предпочтителен следующий, затем предыдущий.
При `false` остаётся числовая позиция браузера с естественным ограничением при уменьшении списка.

`resetKey` обозначает явную смену набора, например нового поискового запроса.
При изменении ключа позиция возвращается к началу без remount и без удаления измеренных высот устойчивых ключей.
Для realtime-обновления существующих элементов оставляйте ключ прежним: не включайте в него время обновления, длину массива или object identity.

## Пустой набор и загрузка

`emptyContent` задаёт штатное пустое состояние. При первичной загрузке пустого источника `isLoading` показывает индикатор.
При фоновой загрузке с уже имеющимися данными строки остаются доступными — индикатор не заменяет весь список.
Scrollable имеет доступную семантику `region`, имя по `aria-label` (по умолчанию `Список`) и содержит семантический список.

## Постраничный источник

Опубликованный режим `hasNextPage: boolean` вместе с `fetchNextPage: () => Promise<unknown>` сохранён.
При `true` callback обязателен; при `false` либо отсутствии `hasNextPage` он не требуется.
При приближении виртуального окна к концу запрашивается следующая страница. Источник добавляет полученные элементы сам.
Один выполняющийся запрос не дублируется; для такого режима backend и cache остаются у consumer.

## Обычный список

`List.Content` отображает весь набор без виртуализации. Он использует те же `items`, `getKey`, `render`, `columns`, `grouping`, `separated` и `className`.
В `Content` включённый `separated` добавляет границу каждой строке, включая последнюю;
в `VirtualizedContent` завершённый набор не получает границу после последней строки.
Не выбирайте его для большого списка только ради сохранения данных: `VirtualizedContent` в полном режиме сохраняет весь источник, ограничивая лишь число смонтированных строк.
