<Title>List</Title>

`List` компонует `Toolbar`, `Content` или `VirtualizedContent` и `Footer`.
Владелец передаёт элементы и их представление: компонент не читает данные, не хранит копию источника и не знает предметных правил приложения.

## Полный источник

Все элементы уже доступны в одном `readonly` массиве. Виртуализация ограничивает только DOM-окно, не набор данных; `hasNextPage` и фиктивный `fetchNextPage` не нужны.
Внешняя область должна иметь ограниченную высоту, иначе прокрутка не получает собственного viewport.

```tsx
import { List } from "@ryuzaki13/react-foundation-ui/list";

<List.VirtualizedContent
	items={items}
	getKey={(item) => item.id}
	render={(item) => <ItemRow item={item} />}
	estimateSize={120}
	overscan={5}
	aria-label="Список записей"
/>;
```

`getKey` должен возвращать уникальный устойчивый ключ записи, а не её текущий индекс.
Измеренные высоты принадлежат ключам: изменение содержимого, перестановка и новые элементы не переносят старую высоту на другую запись.
`estimateSize` — начальная оценка высоты в пикселях, не фиксированная высота строки. По умолчанию используются `120` и `overscan=5`.
Выбирайте оценку, близкую к реальному содержимому; после измерения действует фактическая высота.

## Позиция при изменении набора

`preserveScrollAnchor=true` по умолчанию сохраняет ключ первой видимой строки и смещение внутри неё.
Если эта запись исчезла, выбирается ближайший оставшийся ключ в прежнем порядке; при равном расстоянии предпочтителен следующий, затем предыдущий.
При `false` остаётся числовая позиция браузера с естественным ограничением при уменьшении списка.

`resetKey` обозначает явную смену набора, например нового поискового запроса.
При изменении ключа позиция возвращается к началу без remount и без удаления измеренных высот устойчивых ключей.
Для realtime-обновления существующих элементов оставляйте ключ прежним: не включайте в него время обновления, длину массива или object identity.

## Пустой набор и загрузка

`emptyContent` задаёт штатное пустое состояние. При первичной загрузке пустого источника `isLoading` показывает индикатор.
При фоновой загрузке с уже имеющимися данными строки остаются доступными — индикатор не заменяет весь список.
Scrollable имеет доступную семантику `region`, имя по `aria-label` (по умолчанию `Список`) и содержит семантический список.

## Постраничный источник

Опубликованный режим `hasNextPage: boolean` вместе с `fetchNextPage: () => Promise<unknown>` сохранён.
При `true` callback обязателен; при `false` либо отсутствии `hasNextPage` он не требуется.
При приближении виртуального окна к концу запрашивается следующая страница. Источник добавляет полученные элементы сам.
Один выполняющийся запрос не дублируется; для такого режима backend и cache остаются у consumer.

## Обычный список

`List.Content` отображает весь набор без виртуализации. Он использует те же `items`, `getKey`, `render`, `separated` и `className`.
Не выбирайте его для большого списка только ради сохранения данных: `VirtualizedContent` в полном режиме сохраняет весь источник, ограничивая лишь число смонтированных строк.
