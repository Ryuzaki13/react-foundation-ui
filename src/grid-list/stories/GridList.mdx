`GridList` отображает большой плоский источник как виртуализированную адаптивную сетку.
`GridList.Content` всегда ограничивает DOM видимыми рядами и дополнительными рядами `overscan`;
данные, выбор, поиск и запросы принадлежат consumer.

## Непрерывное размещение

Число колонок определяется по ширине самого контейнера, `minItemWidth` и `gap`.
При resize весь доступный источник заново распределяется по этому числу колонок.
Например, 12 карточек при переходе с четырёх колонок на три образуют четыре полных ряда.

У `List.columns` другой контракт: данные заранее делятся по `columns.count`,
а `minItemWidth` переносит карточки внутри каждого такого ряда. Для общей адаптивной
сетки используйте `GridList`; менять существующий `List` для её получения не требуется.

```tsx
import { GridList } from "@ryuzaki13/react-foundation-ui/grid-list";

<div style={{ height: "36rem" }}>
	<GridList>
		<GridList.Toolbar>
			<FilterControls />
		</GridList.Toolbar>
		<GridList.Content
			items={items}
			getKey={(item) => item.id}
			render={(item) => <ItemCard item={item} />}
			minItemWidth="16rem"
			maxColumns={4}
			gap="md"
			estimateSize={280}
			aria-label="Материалы"
		/>
		<GridList.Footer>
			<SelectionSummary />
		</GridList.Footer>
	</GridList>
</div>;
```

Родитель должен ограничивать высоту. `Toolbar` и `Footer` необязательны и остаются
вне единственной прокручиваемой области. Их содержимое оформляет consumer.
`Content` можно применять отдельно внутри контейнера с ограниченной высотой.

| Настройка      | Контракт                                                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `minItemWidth` | Обязательная корректная положительная CSS-длина, например `16rem` или `var(--ui-width-xl)`. При более узком контейнере остаётся одна колонка по доступной ширине. |
| `maxColumns`   | Необязательный положительный целый предел числа колонок; не фиксирует их количество.                                                                              |
| `gap`          | Расстояние по обеим осям: `none`, `xs`, `sm`, `md`, `lg`, `xl`; по умолчанию `md`. Значения берутся из токенов UI-пакета.                                         |
| `estimateSize` | Предварительная высота целого ряда в пикселях, по умолчанию `120`; после измерения заменяется фактической.                                                        |
| `overscan`     | Число дополнительных рядов с каждой стороны viewport, по умолчанию `5`.                                                                                           |
| `emptyContent` | Представление пустого завершённого источника.                                                                                                                     |

Все колонки имеют одинаковую ширину, включая неполный последний ряд. Высота ряда
равна максимуму его карточек. Следующий ряд начинается ниже этого максимума и `gap`;
это обычная сетка с горизонтально выровненными рядами. Позднее изменение содержимого
карточки также обновляет измеренную высоту.

В стенде доступны поиск, добавление, перестановка, увеличение выбранной карточки,
смена минимальной ширины и сужение контейнера. Поле локальной заметки позволяет
проверить состояние одной карточки при адаптивном перераспределении.

## Ключи, состояние и позиция

`getKey(item, index)` должен возвращать уникальный устойчивый ключ исходной записи.
Не используйте текущий индекс как identity меняющейся коллекции.
Карточки образуют одну плоскую React-коллекцию: смена числа колонок сама по себе
не размонтирует те карточки, которые остаются в DOM. Их локальное состояние и фокус
сохраняются, даже если карточка переходит в другой ряд.

Уход за пределы виртуального DOM-окна размонтирует карточку. Долгоживущее состояние
выбора, редактирования или раскрытия храните у consumer по исходному ключу.

`preserveScrollAnchor=true` по умолчанию сохраняет ключ первой записи видимого ряда
и смещение внутри ряда при изменении источника и геометрии. Если ключ удалён,
выбирается ближайшая сохранившаяся запись в прежнем порядке. `resetKey` явно возвращает
позицию к началу, например при смене поискового запроса. Для обычного обновления
существующих данных оставляйте `resetKey` прежним.

`onVisibleKeysChange(keys)` сообщает исходные ключи всех карточек рядов, пересекающих
viewport, в порядке отображения. Дополнительные ряды `overscan`, заголовки и строка
догрузки исключаются. Callback вызывается после commit при изменении диапазона;
пустой источник, viewport нулевой высоты и освобождение непустого диапазона дают `[]`.
Сохраняйте стабильную функцию callback, чтобы не менять consumer при каждой отрисовке.

## Группы

`grouping?: GridListGrouping<T>` объединяет записи с одинаковым ключом группы.
`grouping.getKey(item, index)` получает исходную запись и её индекс.
Порядок групп задаёт первое появление ключа, а внутри группы сохраняется порядок источника.
`grouping.render(key, items)` получает ключ и `readonly` массив всех записей группы.

Заголовок занимает всю ширину. Каждая группа самостоятельно заполняет адаптивные ряды;
неполный хвост одной группы не дополняется карточками следующей.

```tsx
<GridList.Content
	items={items}
	getKey={(item) => item.id}
	render={(item) => <ItemCard item={item} />}
	minItemWidth="16rem"
	grouping={{
		getKey: (item) => item.categoryId,
		render: (key, groupItems) => (
			<h3>
				{key}: {groupItems.length}
			</h3>
		)
	}}
/>
```

## Загрузка и постраничный источник

`isLoading` при пустом наборе показывает первичную загрузку. При уже имеющихся
карточках фоновая загрузка сохраняет их доступными. `hasNextPage` не нужен,
если весь источник уже загружен.

Для постраничного источника передайте `hasNextPage` вместе с `fetchNextPage`.
При `true` callback обязателен. По достижении края виртуального окна сетка запрашивает
следующую страницу; consumer дополняет `items`. Новые карточки сначала заполняют
неполный последний ряд, затем создают следующие. Выполняющийся запрос не дублируется.
Первичная загрузка, обработка transport-ошибок и данные запроса остаются у consumer.

## SSR и доступность

Сервер не читает browser API и не знает ширину контейнера. SSR и первое клиентское
дерево содержат одинаковую область с предварительной высотой; карточки DOM-окна
появляются после commit измерений. Геометрия уточняется при гидратации без отключения SSR.
Если важен предварительный резерв высоты, выбирайте `estimateSize` близким к реальному ряду.

Viewport имеет семантику именованного `region`, принимает `aria-label` и доступен
с клавиатуры. Карточки образуют список: `aria-posinset` и `aria-setsize` относятся
к отображаемому порядку полного доступного источника. Вспомогательные измерители,
заголовки и sentinel не выдаются за записи данных. Доступность действий внутри
карточки обеспечивает её собственное представление.
