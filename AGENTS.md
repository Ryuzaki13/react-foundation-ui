# Правила изменений Foundation UI

- Общие UI-компоненты и их модели принадлежат этому пакету и не должны зависеть от предметных модулей, Router или запросов приложения.
- Разделять независимые логические блоки пустыми строками. Проверять читаемость кода отдельно от результата Prettier.
- Новые React-компоненты размещать по одному в файле. Вынесение компонента должно отражать его ответственность, а не добавлять пустую обёртку.
- Не создавать DOM-контейнер только ради `data-*` или тестового селектора. Размещать машинный идентификатор на существующем смысловом элементе.
- Авторские тексты интерфейса, комментарии и документацию писать на русском языке; для многоточия использовать три ASCII-точки (`...`). Символ Unicode U+2026 запрещён. Не заменять его массово в пользовательских данных, регулярных выражениях и внешних материалах.
- Сохранять опубликованные exports, формы интерфейсов и изменяемость существующих props. Расширение API не должно скрывать несовместимое изменение под minor/patch-релизом. Major-релизы пакета запрещены.
